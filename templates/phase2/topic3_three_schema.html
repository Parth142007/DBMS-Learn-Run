3. Three-Schema Architecture (ANSI/SPARC)

Master the fundamental three levels of database abstraction — External (View), Conceptual (Logical), and Internal (Physical) — along with schema mappings and the critical distinction between tiers and schemas.

3.1

Introduction to Three-Schema Architecture

Proposed in 1975 by the ANSI/X3/SPARC (American National Standards Institute / Standards Planning And Requirements Committee), the Three-Schema Architecture was created to achieve a monumental goal in database engineering:

The Prime Directive of Three-Schema Architecture: To completely decouple user applications from the physical database, hide low-level storage complexities through data abstraction, allow different users to view customized slices of data, and provide the technical mechanism for data independence.

A Schema is the overall formal description of the database structure (tables, fields, data types, constraints). The Three-Schema architecture partitions this description into three distinct levels of abstraction: External Level, Conceptual Level, and Internal Level.

3.2

External Schema — View Level (Highest Abstraction)

The External Schema (often called the View Level) describes the specific portion of the database that is relevant to a particular user group while strictly hiding the remainder of the database.

Critical Concept: An external schema is a virtual projection (view) of the database, NOT a separate physical copy of the database! Multiple users access the exact same underlying tables, but through different tailored lenses.
College Example: 3 Distinct External Views Over One University Database:
View 1
Student Portal View

What the student sees: Their own Roll Number, full name, enrolled courses, attendance percentage, and GPA.

Hidden: Other students' GPAs, faculty salaries, system logs.
View 2
Faculty / Professor View

What the professor sees: Course roster, student roll numbers, attendance entry checkboxes, and marks entry forms.

Hidden: Student tuition fee payment status, financial aid.
View 3
Accounts & Finance View

What the accountant sees: Student ID, total fee due, payment receipt numbers, bank transaction IDs.

Hidden: Academic course syllabus details, assignment scores.
Primary Security Benefit: By confining user roles to their respective external schemas, malicious or curious users cannot accidentally or intentionally browse sensitive records outside their authorized clearance.
3.3

Conceptual Schema — Logical Level (Middle Level)

The Conceptual Schema (also known as the Logical Level) describes the entire logical structure of the whole database for all users combined.

It acts as the single central blueprint that defines all entities, data types, relationships between entities, and enterprise-wide integrity constraints.

What the Conceptual Schema Contains:
  • All Tables / Entities: students, departments, courses, registrations.
  • All Attributes & Data Types: student_id (INT), first_name (VARCHAR), gpa (DECIMAL).
  • All Relationships: Students belong to Departments; Registrations connect Students and Events.
  • Integrity Rules & Constraints: PRIMARY KEY, FOREIGN KEY, NOT NULL, CHECK (gpa >= 0.0).

Crucial Insight: The conceptual level is completely unconcerned with how bytes or tracks are physically laid out on hard disks or what index algorithms are utilized. It represents what data is stored, not how the hardware stores it.

3.4

Internal Schema — Physical Level (Lowest Level)

The Internal Schema (or Physical Level) describes the low-level physical storage structure, file organization, and access paths of the database on storage hardware.

It specifies the exact technical details required by the operating system and storage controllers to physically read and write bits on magnetic disks or solid-state drives (SSDs).

Block Allocation 4KB or 16KB disk page allocations on disk storage.
Record Layout Byte offsets, fixed vs variable length fields, null bitmasks.
B+ Tree Indexes Physical tree pointers for accelerated disk seek operations.
Data Compression InnoDB zlib page compression and encryption at rest.
Difference between Logical & Physical Representation: Logically, a student record is seen as a clean row: (101, 'Aarav', 9.45). Physically, it is a binary sequence of raw bytes, preceded by a 5-byte record header, stored at byte offset 0x00A4F0 inside an InnoDB tablespace file (students.ibd) on an NVMe SSD.
3.5

Mappings Between the Three Levels

The superpower of the Three-Schema architecture lies in its Schema Mappings. A mapping is a translation protocol maintained by the DBMS that connects a representation at one level to a representation at another level:

1. External-to-Conceptual Mapping

Translates a query written against an end-user's external view into an equivalent query on the overall conceptual schema tables.

View Attribute full_name ↔ CONCAT(first_name, ' ', last_name) in students
2. Conceptual-to-Internal Mapping

Translates conceptual relational operations into physical disk block reads, index seeks, and record byte offset lookups.

Table students ↔ File students.ibd, Page 38, B+ Tree Index on Root 0x4B

3.6

Advantages of Three-Schema Architecture

1. Data Abstraction

Users and application developers are freed from knowing storage details like disk block offsets or B+ tree leaf sizes. They query pure logical concepts.

2. Tailored User Views

Different departments see customized views of the exact same database. A student never sees faculty salary columns, enhancing confidentiality.

3. Data Independence

Modifying storage hardware or adding an index does not disrupt application code, because intermediate mappings absorb the change.

3.7

Critical Distinction: Three-Schema vs. Three-Tier

The #1 Most Common Exam Misconception Clarified!

Students frequently confuse Three-Schema Architecture with Three-Tier Architecture because both share the number "three". However, they answer two fundamentally different architectural questions:

Data Modeling Concept
Three-Schema Architecture (ANSI/SPARC)

Answers: "What data is seen and how is it abstracted inside the DBMS?"

  • Pertains strictly to data abstraction inside the database system.
  • Components: External Schema, Conceptual Schema, Internal Schema.
  • Can exist even on a single standalone computer!
Software Deployment Concept
Three-Tier Architecture (Client-Server)

Answers: "Where does the software physically run across computers and networks?"

  • Pertains to physical software and hardware distribution.
  • Components: Presentation Tier (Browser), Application Tier (Server), Database Tier (DBMS).
  • Spans multiple physical machines connected over networks.
Comparison Dimension Three-Schema Architecture Three-Tier Architecture
Primary Domain Database Design & Data Abstraction Software Engineering & Network Deployment
The Three Elements External Level, Conceptual Level, Internal Level Presentation Layer, Application Layer, Database Layer
Role of Network Not required; schemas describe data layout Essential; tiers communicate over LAN/Internet
Main Goal Achieve Data Independence and custom views Achieve Scalability, Security, and Thin Clients

Model Answer: External-to-Conceptual mapping is the correspondence maintained by the DBMS that maps attributes and records in a specific user's external view to the corresponding tables and columns in the global conceptual schema. It ensures that queries written against a customized view can be correctly translated to the underlying logical tables.

Model Answer:
  1. External Level: A student viewing their individual grade card on the mobile app. They see only their own roll number, name, and GPA.
  2. Conceptual Level: The university's global relational schema: students(student_id, roll_no, first_name, dept_id, gpa), departments(dept_id, dept_name), with primary/foreign keys and integrity constraints.
