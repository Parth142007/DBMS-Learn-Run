10. Nested Subqueries

Master the technique of nesting queries inside queries: scalar subqueries, multi-row lookups with IN, ANY, and ALL, derived tables in the FROM clause, and powerful correlated subqueries using EXISTS and NOT EXISTS.

10.1

What is a Subquery?

A subquery (also called an inner query or nested query) is a SELECT statement embedded inside another SQL statement (the outer query). Subqueries are enclosed within parentheses (...) and can be placed in the WHERE, FROM, HAVING, or SELECT clauses.

Anatomy of a Nested Subquery:
-- Outer Query (main query that formats and returns the final result) SELECT name, gpa FROM students WHERE gpa > ( -- Inner Query (subquery executed to compute a dynamic benchmark) SELECT AVG(gpa) FROM students );
Execution order: Inner Query evaluates first → calculates average (e.g. 3.65) → Outer Query evaluates second using WHERE gpa > 3.65.
Subquery Types by Cardinality (Shape of Result):
Scalar Subquery
1 Row × 1 Column

Returns a single value (e.g., AVG(gpa)). Used with comparison operators like =, >, <, !=.

Multi-Row Subquery
N Rows × 1 Column

Returns a list of values. Used with set operators like IN, NOT IN, ANY, ALL.

Derived Table
N Rows × M Columns

Placed in the FROM clause. Acts as a virtual in-memory table and must have an alias.

10.2

Scalar Subqueries in WHERE

A scalar subquery returns exactly one value. This allows you to write dynamic filters without hardcoding values.

Live Query: Students with Above-Average GPA Scalar Comparison

The inner query computes the campus-wide average GPA. The outer query displays all students whose GPA strictly exceeds this dynamic average:

SELECT student_id, first_name, semester, gpa FROM students WHERE gpa > ( SELECT AVG(gpa) FROM students ) ORDER BY gpa DESC;
Common Error: Subquery returns more than 1 row (Error 1242): If you use a scalar operator like WHERE gpa = (SELECT gpa FROM students), MySQL throws: ERROR 1242: Subquery returns more than 1 row. Because = expects a single scalar value, you cannot supply a multi-row list!
10.3

Multi-Row Subqueries: IN, ANY, ALL

When a subquery returns a column containing multiple rows, you must use set-comparison operators:

Operator Meaning Example Condition
IN True if the value matches ANY element in the subquery's result set. WHERE dept_id IN (SELECT dept_id FROM ...)
NOT IN True if the value matches NO element in the subquery's result set. WHERE student_id NOT IN (SELECT student_id ...)
> ALL True if the value is strictly greater than EVERY value returned by the subquery. WHERE gpa > ALL (SELECT gpa FROM ...)
> ANY True if the value is strictly greater than AT LEAST ONE value in the subquery. WHERE gpa > ANY (SELECT gpa FROM ...)
Live Query: Students in Specific Departments via IN Multi-Row IN

Select all students belonging to departments whose department code begins with 'C' (Computer Science & Civil Engineering):

SELECT student_id, name, dept_id, gpa FROM students WHERE dept_id IN ( SELECT dept_id FROM departments WHERE dept_code LIKE 'C%' ) ORDER BY student_id ASC;
10.4

Correlated Subqueries & EXISTS

In a non-correlated subquery, the inner query runs once independently of the outer query. In a correlated subquery, the inner query references a column from the outer query (e.g. r.student_id = s.student_id). As a result, the inner query re-evaluates for every single row examined by the outer query!

The EXISTS Operator:

EXISTS returns TRUE as soon as the inner query produces at least one row, and FALSE if the inner query produces zero rows. Because it stops scanning immediately upon finding the first matching row (short-circuiting), it is often highly efficient.

Live Query: Unregistered Students via Correlated NOT EXISTS Correlated Subquery

Find all students who have zero event registrations. For each student s in the outer query, the inner query checks if any registration exists with matching student_id:

SELECT s.student_id, s.first_name, s.last_name, s.email, s.dept_id FROM students s WHERE NOT EXISTS ( SELECT 1 FROM registrations r WHERE r.student_id = s.student_id ) ORDER BY s.student_id ASC;
The Famous NOT IN NULL Trap! If the subquery returns even a single row with a NULL value (for example, [1, 2, NULL]), the expression val NOT IN (1, 2, NULL) evaluates to UNKNOWN (NULL) for every value due to 3-valued logic. As a consequence, the outer query returns 0 rows! NOT EXISTS never suffers from this trap because it only checks for the existence of rows.
10.5

Subqueries in the FROM Clause (Derived Tables)

A subquery in the FROM clause creates a temporary, unnamed result set known as a derived table. In MySQL, every derived table MUST be assigned a table alias, or MySQL will reject it with: ERROR 1248: Every derived table must have its own alias.

Live Query: Department Statistics Derived Table FROM Clause Subquery

This query aggregates department headcount inside a derived table aliased as dept_stats, and then queries that summary table:

SELECT dept_stats.dept_id, dept_stats.student_count, dept_stats.avg_gpa FROM ( -- Derived table subquery SELECT dept_id, COUNT(*) AS student_count, ROUND(AVG(gpa), 2) AS avg_gpa FROM students GROUP BY dept_id ) AS dept_stats WHERE dept_stats.student_count >= 2 ORDER BY dept_stats.avg_gpa DESC;
10.6

Subqueries vs JOINs: Architectural Tradeoffs

Students often wonder: "Should I write a JOIN or a Subquery?" In modern relational database engines like MySQL 8, the query optimizer often transforms subqueries into joins internally. However, each construct has distinct strengths:

Criteria JOINs Subqueries
Returning Columns Can retrieve columns from both tables in the final SELECT. Outer query can only output columns from the outer table (unless subquery is in FROM).
Readability Best when combining related entities (e.g. students & departments). Best for isolated scalar calculations (e.g. gpa > AVG(gpa)) or existence tests.
Correlated Overhead Usually set-based and heavily optimized with index scans. Correlated subqueries can execute $O(N)$ times if not unnested by the optimizer.

Practice Exercises

Exercise 1 (Moderate) Nested Scalar Subquery

Students Above Minimum IT GPA:

Write a query to find all students in any department whose GPA is strictly higher than the highest GPA in Department 4 (IT). Display their student_id, name, dept_id, and gpa.

Hint: Use a scalar subquery: WHERE gpa > (SELECT MAX(gpa) FROM students WHERE dept_id = 4).
Exercise 2 (Advanced) Correlated Subquery

Students Above Their Own Department's Average:

Write a correlated subquery that displays students whose GPA is higher than the average GPA of their specific department.

Hint: Correlate the subquery on dept_id: WHERE s.gpa > (SELECT AVG(sub.gpa) FROM students sub WHERE sub.dept_id = s.dept_id).
