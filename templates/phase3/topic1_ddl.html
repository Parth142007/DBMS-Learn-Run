1. DDL — Data Definition Language

Master the structural commands that build, alter, and destroy database schemas: CREATE, ALTER, DROP, and TRUNCATE, along with table constraints and implicit commit mechanics.

1.1

What is DDL and Why is it Essential?

Data Definition Language (DDL) consists of the subset of SQL commands responsible for defining, altering, and managing the structure of database objects — such as databases, tables, columns, indexes, and constraints.

Key Principle: DDL operations modify the database schema and metadata stored in the Data Dictionary (System Catalog). Unlike DML (which alters the rows *inside* a table), DDL alters the *container* itself.
Crucial MySQL Technical Behavior — Implicit Commits: In MySQL, all DDL statements (such as CREATE TABLE, ALTER TABLE, DROP TABLE, and TRUNCATE TABLE) cause an implicit transaction commit. You cannot issue a ROLLBACK statement to undo a DDL command! Once executed, schema changes are permanently written to disk.
Dedicated Safe Sandbox: practice_students To protect core curriculum tables (departments, students, events, etc.) for JOIN and query lessons, all DDL drop/alter experiments are safely performed on the practice_students table.

Core DDL Commands & Syntax

1. CREATE TABLE & Constraints Structure Creator

CREATE TABLE specifies the table name, column definitions (name and data type), and integrity constraints.

CREATE TABLE table_name (
    column1 datatype [CONSTRAINTS],
    column2 datatype [CONSTRAINTS],
    ...
    [CONSTRAINT constraint_name CONSTRAINT_DEFINITION]
) ENGINE=InnoDB;
Constraint Meaning & Enforcement Example Usage
PRIMARY KEY Uniquely identifies each row; strictly forbids duplicate values and NULLs. student_id INT AUTO_INCREMENT PRIMARY KEY
FOREIGN KEY Enforces referential integrity pointing to a primary key in another table. FOREIGN KEY (dept_id) REFERENCES departments(dept_id)
UNIQUE Ensures all values in a column are distinct across the table. roll_no VARCHAR(20) NOT NULL UNIQUE
NOT NULL Guarantees that a column cannot store NULL (missing) values. first_name VARCHAR(50) NOT NULL
DEFAULT Supplies a default value when no value is provided on INSERT. gpa DECIMAL(3,2) DEFAULT 7.50
CHECK Validates that inserted/updated values satisfy a boolean expression. CHECK (gpa >= 0.00 AND gpa <= 10.00)
Live Executable Example: 
DESCRIBE practice_students;
2. ALTER TABLE Structure Mutator

ALTER TABLE modifies the schema of an existing table without dropping it. Common actions include:

  • ADD COLUMN: Adds a new field to the table.
  • MODIFY COLUMN: Changes a column's data type or nullability constraint.
  • DROP COLUMN: Permanently removes a column from the table.
  • ADD CONSTRAINT: Adds a new check or unique constraint.
Example A: Add a new column 
ALTER TABLE practice_students 
ADD email VARCHAR(100) DEFAULT 'pending@college.edu';
Example B: Modify column data type 
ALTER TABLE practice_students 
MODIFY city VARCHAR(80) NOT NULL;
3. DROP TABLE vs. TRUNCATE TABLE Destructive Commands

Students frequently confuse DROP, TRUNCATE, and DELETE. Here is their structural contrast:

Feature / Command DROP TABLE TRUNCATE TABLE DELETE FROM table
SQL Category DDL DDL DML
Effect on Table Structure Completely deletes the table definition and all data from database. Preserves the table structure and columns, but wipes all rows. Preserves the table structure; deletes selected rows.
WHERE Clause Support No (Drops entire object) No (Wipes entire table at storage engine level) Yes (Can delete specific rows via WHERE)
Auto-Increment Reset N/A (Table is destroyed) Resets AUTO_INCREMENT counter back to 1. Does NOT reset the AUTO_INCREMENT counter.
Performance Instant (Deletes metadata & storage file) Blazing Fast (Drops and recreates storage pages) Slower (Logs row-by-row deletions for rollback)
