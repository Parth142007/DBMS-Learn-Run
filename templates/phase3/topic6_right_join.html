6. RIGHT JOIN — Preserving All Right-Side Records

Understand how Right Outer Joins preserve every single record from the right-hand table, pairing unmatched left-side columns with NULL, and why every RIGHT JOIN can be rewritten as a LEFT JOIN.

6.1

How Does a RIGHT JOIN Operate?

A RIGHT JOIN (or RIGHT OUTER JOIN) is the exact mirror image of a LEFT JOIN. It returns all records from the right table (Table B), along with matched records from the left table (Table A).

The Right Join Rule: If a row in Table B finds no matching row in Table A, all columns from Table A are set to NULL.
Diagram 6.1: RIGHT OUTER JOIN Set Representation

Figure 6.1: The entire right table (green) is preserved. Any row in Table B with zero matches in Table A displays NULL on the left side.

Industry Best Practice — Why LEFT JOIN is Preferred: SELECT * FROM A RIGHT JOIN B is 100% semantically equivalent to SELECT * FROM B LEFT JOIN A! Most professional database developers standardize on LEFT JOIN because reading left-to-right matches natural Western reading direction.
6.2

Live Verified Example: Events Without Registrations

In our university database, Event 6 (Cybersecurity & Cloud Summit 2026) was intentionally seeded with 0 registrations. If we right join registrations with events, Event 6 is preserved with registration_id = NULL:

Executable RIGHT JOIN Query: 
SELECT e.event_id, 
       e.event_title, 
       e.capacity, 
       r.registration_id, 
       r.status 
FROM registrations r 
RIGHT JOIN events e 
  ON r.event_id = e.event_id 
ORDER BY e.event_id ASC;
Result Interpretation: Events 1 through 5 show their registration records. Event 6 (Cybersecurity Summit) appears on the final row with registration_id = NULL and status = NULL, proving that it has zero attendees registered!
