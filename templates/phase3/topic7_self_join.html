7. SELF JOIN — Joining a Table to Itself

Learn how to model self-referencing hierarchies (such as student-to-mentor or employee-to-manager) by joining two distinct logical alias instances of the exact same physical table.

7.1

Why and How Do You Join a Table to Itself?

A SELF JOIN is a regular join in which a table is joined with itself. It is commonly used when records within the same table have hierarchical or associative relationships with each other — such as an employee reporting to a manager, or a junior student being mentored by a senior student.

The Golden Rule of Self Joins — Aliases are Mandatory! Because both sides of the join refer to the exact same table, you MUST assign distinct table aliases (e.g. students s and students m) so the database engine can distinguish which instance represents the student (mentee) and which instance represents the mentor!

7.2

Live Executable Examples & Mentor Output

1. List Students and Their Assigned Peer Mentors (INNER JOIN): 
SELECT s.roll_no AS mentee_roll, 
       CONCAT(s.first_name, ' ', s.last_name) AS student_name, 
       s.semester AS student_sem, 
       CONCAT(m.first_name, ' ', m.last_name) AS mentor_name, 
       m.semester AS mentor_sem 
FROM students s 
INNER JOIN students m 
  ON s.mentor_id = m.student_id 
ORDER BY s.roll_no ASC;
2. Include Senior Students Who Have No Mentor (LEFT SELF JOIN): 
SELECT s.roll_no, 
       CONCAT(s.first_name, ' ', s.last_name) AS student_name, 
       IFNULL(CONCAT(m.first_name, ' ', m.last_name), 'Senior Peer Mentor (None)') AS mentor_name 
FROM students s 
LEFT JOIN students m 
  ON s.mentor_id = m.student_id 
ORDER BY s.student_id ASC;
