8. CROSS JOIN & Comprehensive Join Comparison

Understand the Cartesian product — how every row in Table A pairs with every row in Table B — the catastrophic performance risks of accidental cross joins, and a complete multi-dimensional comparison of all 5 relational joins.

8.1

What is a CROSS JOIN (Cartesian Product)?

A CROSS JOIN returns the Cartesian product of the two joined tables. That is, it combines every single row of Table A with every single row of Table B, without evaluating any join condition (no ON clause).

Result Set Cardinality Formula: Total Rows = |Table A| × |Table B|

In our database, departments has 5 rows and events has 6 rows. Their CROSS JOIN produces exactly 5 × 6 = 30 rows.

THE DANGER OF UNINTENDED CROSS JOINS! If you write SELECT * FROM table1, table2 and forget the join condition in the WHERE clause, SQL defaults to a Cartesian product! If table1 has 10,000 rows and table2 has 10,000 rows, the query attempts to generate 100,000,000 rows, which can exhaust RAM and crash your database server! Always use explicit modern JOIN syntax with an ON clause to prevent accidental Cartesian explosions.
8.2

Live Safe CROSS JOIN Example

Legitimate use cases for CROSS JOIN include generating permutations, scheduling matrices, or pairing all academic departments with campus event venues:

Bounded CROSS JOIN Query: 
SELECT d.dept_code, 
       d.dept_name, 
       e.event_title, 
       e.location 
FROM departments d 
CROSS JOIN events e 
ORDER BY d.dept_code ASC 
LIMIT 15; -- Capped for display safety
8.3

Comprehensive Comparison of All 5 SQL Joins

Multi-Dimensional Relational Join Comparison Matrix
Join Type Preserved Rows Unmatched Handling Generates NULLs? Ideal Real-World Use Case
INNER JOIN Only matching rows in BOTH tables. Discarded completely. No (unless actual column stores NULL). Finding confirmed registrations, student departments.
LEFT JOIN ALL rows from Left table + matches from Right table. Right columns padded with NULL. Yes (for unmatched right rows). Finding inactive students, items with zero sales.
RIGHT JOIN ALL rows from Right table + matches from Left table. Left columns padded with NULL. Yes (for unmatched left rows). Finding events with zero signups (or reverse order in LEFT JOIN).
SELF JOIN Depends on INNER or LEFT join condition on the same table. Filtered by join condition on self aliases. Yes (if using LEFT SELF JOIN). Mentors & students, employees & managers, category trees.
CROSS JOIN Every row in Table A × Every row in Table B. No join condition evaluated. No (unless raw data contains NULL). Generating schedule combinations, product size × color grids.
