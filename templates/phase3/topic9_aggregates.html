9. Aggregate Functions, GROUP BY & HAVING

Learn how relational database engines perform multi-row calculations: summarizing populations with COUNT, SUM, AVG, MIN, and MAX, partitioning datasets with GROUP BY, and filtering aggregated groups with HAVING.

9.1

What are Aggregate Functions?

An aggregate function takes a set of values from multiple rows in a column and compresses them into a single scalar summary value. Unlike scalar functions (such as UPPER() or ROUND()) that operate row-by-row, aggregate functions operate across an entire set of rows.

Row Reduction

Collapses 1,000 student records into a single average GPA or total head count.

NULL Value Ignorance

Aggregate functions (except COUNT(*)) automatically ignore NULL values during calculation.

Partitioned Summary

When combined with GROUP BY, calculates separate summaries for each subset/category.

Visualizing Aggregation & Grouping

Every group bucket collapses into exactly one output row containing aggregate calculations.

9.2

The Core 5 Aggregate Functions

Function Purpose & Syntax Handling of NULLs Example Expression
COUNT(*) Counts total rows in the table or group, regardless of nulls or duplicates. Includes NULL rows COUNT(*)
COUNT(col) Counts non-NULL values present in the specified column. Ignores NULLs COUNT(mentor_id)
COUNT(DISTINCT col) Counts unique, non-NULL values present in the column. Ignores NULLs COUNT(DISTINCT dept_id)
SUM(col) Calculates the arithmetic total of all non-NULL numeric values. Ignores NULLs SUM(capacity)
AVG(col) Calculates arithmetic mean: SUM(col) / COUNT(col). Ignores NULLs (divisor is non-NULL count!) ROUND(AVG(gpa), 2)
MIN(col) Finds smallest non-NULL value (works on numbers, dates, strings). Ignores NULLs MIN(gpa)
MAX(col) Finds largest non-NULL value (works on numbers, dates, strings). Ignores NULLs MAX(gpa)
Global Aggregation on students Demonstrating COUNT vs COUNT(col)

In our university database, exactly 10 students exist. However, students 1 and 4 do not have an assigned mentor (mentor_id IS NULL). Notice the difference between COUNT(*) and COUNT(mentor_id):

-- Global aggregate metrics across all students in the database SELECT COUNT(*) AS total_students, COUNT(mentor_id) AS students_with_mentor, ROUND(AVG(gpa), 2) AS campus_avg_gpa, MIN(gpa) AS lowest_gpa, MAX(gpa) AS highest_gpa FROM students;
9.3

The GROUP BY Clause

Without GROUP BY, aggregate functions collapse the entire table into a single row. The GROUP BY clause partitions rows having matching values in designated columns into groups, then calculates the aggregate function independently for each group.

Syntax & Golden Rules of GROUP BY:
SELECT column1, column2, AGGREGATE_FUNCTION(column3) FROM table_name GROUP BY column1, column2 ORDER BY AGGREGATE_FUNCTION(column3) DESC;
The ONLY_FULL_GROUP_BY Rule: In standard SQL (and MySQL 8's default ONLY_FULL_GROUP_BY SQL mode), every column in your SELECT list must either be:
  1. Explicitly named in the GROUP BY clause, OR
  2. Enclosed inside an aggregate function (such as COUNT(), AVG(), etc.).
Selecting a raw column like name without grouping by it produces: ERROR 1055: Expression is not in GROUP BY clause and contains nonaggregated column.
Live Query: Department Enrolment & GPA Summary JOIN + GROUP BY + ORDER BY

This query joins departments with students, groups by department, counts students, and sorts from highest to lowest enrollment:

SELECT d.dept_code, d.dept_name, COUNT(s.student_id) AS total_students, COALESCE(ROUND(AVG(s.gpa), 2), 0.00) AS avg_gpa FROM departments d LEFT JOIN students s ON d.dept_id = s.dept_id GROUP BY d.dept_id, d.dept_code, d.dept_name ORDER BY total_students DESC, d.dept_code ASC;
9.4

HAVING vs WHERE: Filtering Aggregated Data

One of the most frequent mistakes students make is trying to filter groups with a WHERE clause (e.g., WHERE COUNT(*) > 2). This fails because WHERE filters rows before aggregation occurs. To filter aggregated buckets, you must use HAVING.

Feature WHERE Clause HAVING Clause
Execution Stage Evaluated BEFORE rows are grouped. Evaluated AFTER groups are created and aggregates computed.
Level of Filtering Filters individual candidate records/rows. Filters collapsed summary groups/buckets.
Can Use Aggregates? NO (causes Error 1111) YES (e.g. HAVING COUNT(*) >= 2)
Best Used For Filtering raw data like status = 'Confirmed' or semester = 3. Filtering aggregated results like COUNT(*) > 5 or AVG(gpa) >= 3.5.
Logical Execution Order in SQL:

Notice where WHERE and HAVING fit in the engine's logical evaluation pipeline:

1. FROM / JOIN 2. WHERE (Row Filter) 3. GROUP BY 4. HAVING (Group Filter) 5. SELECT 6. DISTINCT 7. ORDER BY 8. LIMIT
Query using both WHERE and HAVING Filter Rows THEN Filter Groups

Find events that have at least 2 Confirmed registrations (uses WHERE to filter for 'Confirmed' status, then HAVING to filter for counts ≥ 2):

SELECT e.event_id, e.event_title AS event_name, COUNT(r.registration_id) AS confirmed_registrations FROM events e JOIN registrations r ON e.event_id = r.event_id WHERE r.status = 'Confirmed' -- Filters rows before grouping GROUP BY e.event_id, e.event_title HAVING confirmed_registrations >= 2 -- Filters groups after aggregation ORDER BY confirmed_registrations DESC;
