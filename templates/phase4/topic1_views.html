1. Database Views & Updatable Views

Understand virtual tables in relational databases — how views provide data abstraction and security, how underlying queries execute on demand, when views can accept INSERT/UPDATE statements, and how WITH CHECK OPTION preserves data integrity.

1.1

What is a Database View?

A database view is a virtual table whose contents are defined by a stored SQL SELECT query. Unlike a physical base table, a view does not store physical row data on the disk (with standard relational engines like MySQL). Instead, whenever you query a view, the database engine executes the underlying query dynamically and returns the current, live data from the base tables.

Dimension Base Table Database View
Disk Storage Stores actual data records, row tuples, and indexes on disk. Stores only the query definition in the data dictionary. Zero row data on disk.
Data Freshness Direct source of truth. Always 100% synchronized with the base tables in real time.
Primary Purpose Persistent relational entity storage. Security restriction, query simplification, and data abstraction.
Data Independence Internal & Conceptual schema levels. External schema level (Three-Schema ANSI/SPARC architecture).
Core Motivations for Using Views:
1. Security & Privacy

Expose only non-sensitive columns. For instance, a student public roster view hides phone numbers, home addresses, and private GPAs.

2. Query Simplification

Encapsulates complex multi-table joins or aggregate expressions so application developers write simple SELECT * FROM view_name.

3. Logical Independence

If conceptual tables are split or renamed, views can reproduce the old schema, preventing legacy application code from breaking.

4. Standardized Metrics

Ensures all reporting systems calculate business KPIs (like department occupancy or GPA averages) using the identical formula.

1.2

Creating and Managing Views

In MySQL 8, views are defined using CREATE VIEW or CREATE OR REPLACE VIEW:

-- 1. Create or Replace a View CREATE OR REPLACE VIEW vw_student_mentorship AS SELECT s.student_id, s.roll_no, CONCAT(s.first_name, ' ', s.last_name) AS student_name, d.dept_code, s.semester, s.gpa, IFNULL(CONCAT(m.first_name, ' ', m.last_name), 'No Mentor') AS mentor_name FROM students s INNER JOIN departments d ON s.dept_id = d.dept_id LEFT JOIN students m ON s.mentor_id = m.student_id; -- 2. Querying the View just like a normal table SELECT * FROM vw_student_mentorship WHERE dept_code = 'CSE'; -- 3. Inspecting the View Definition from the Data Dictionary SHOW CREATE VIEW vw_student_mentorship; -- 4. Dropping a View DROP VIEW IF EXISTS vw_student_mentorship;
Note on Dropping Views vs Base Tables: Executing DROP VIEW vw_name; drops only the virtual definition. The base tables (e.g., students and departments) and their physical data rows are completely unaffected.
1.3

Updatable Views & WITH CHECK OPTION

Can you run an UPDATE, INSERT, or DELETE statement on a view? In MySQL, the answer is: Only if the view is updatable!

A view is updatable if there is a direct, unambiguous 1-to-1 relationship between the rows in the view and the rows in the underlying base table. When you update a row in an updatable view, MySQL directly translates that into an update on the base table.

What Makes a View Updatable?
  • Derived from a single base table.
  • Contains the primary key or unique identifier of that table.
  • Every column in the view maps directly to an underlying physical column (no expressions or aggregates).
What Makes a View NOT Updatable?
  • Aggregate functions: COUNT(), SUM(), AVG(), MIN(), MAX().
  • GROUP BY or HAVING clauses.
  • DISTINCT or UNION / UNION ALL.
  • Calculated columns or window functions.
The Role of WITH CHECK OPTION:

Suppose you create a view of honor students: WHERE gpa >= 8.00. Without WITH CHECK OPTION, an application could update a student through the view to have gpa = 5.00. The update would succeed, and the row would immediately "vanish" from the view!

Adding WITH CHECK OPTION instructs MySQL to reject any INSERT or UPDATE statement that would cause the affected row to no longer satisfy the view's WHERE condition, throwing: ERROR 1369 (HY000): CHECK OPTION failed.

Create Public Student Directory View:

Write a CREATE OR REPLACE VIEW statement named vw_student_public_directory that selects student_id, roll_no, first_name, last_name, and email from the students table, intentionally omitting private fields like phone and gpa.

Exercise 1.2 (Advanced) WITH CHECK OPTION

High-Performing Department View with Check Option:

Explain why updating a view defined with GROUP BY throws an error in MySQL, and write the SQL to create a view over courses that only allows inserting courses with credits between 3 and 4 with WITH CHECK OPTION.

Hint: A GROUP BY collapses multiple rows into a summary row, meaning MySQL has no 1-to-1 mapping to determine which specific underlying base row to update! For the course view: CREATE VIEW vw_core_courses AS SELECT * FROM courses WHERE credits BETWEEN 3 AND 4 WITH CHECK OPTION;
