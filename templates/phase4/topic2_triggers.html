2.1

What is a Database Trigger?

A database trigger is a specialized stored program in MySQL that automatically fires (executes) in response to a specific Data Manipulation Language (DML) event on a particular base table.

Unlike standard stored procedures, a trigger cannot be called manually (there is no CALL my_trigger()). Instead, it runs automatically whenever an INSERT, UPDATE, or DELETE statement affects rows in the bound table.

2.2

The 6 Trigger Types & NEW / OLD Records

In MySQL, every trigger combines one of two timings (BEFORE or AFTER) with one of three DML events (INSERT, UPDATE, or DELETE), yielding exactly 6 trigger permutations:

BEFORE INSERT

Fires before new tuple is saved. Best for validating constraints or transforming input data (e.g. setting NEW.email = LOWER(NEW.email)).

AFTER INSERT

Fires immediately after a tuple is saved. Ideal for audit logging, notifying related tables, or writing to history logs.

BEFORE UPDATE

Fires prior to changing columns. Allows comparing OLD vs NEW values (e.g., preventing a student's GPA from dropping below 0).

AFTER UPDATE

Fires after row modification. Ideal for recording what changed, who changed it, and tracking historic value differences.

BEFORE DELETE

Fires prior to row deletion. Useful for verifying deletion prerequisites or blocking deletion of critical records.

AFTER DELETE

Fires after row removal. Used to copy the removed record into an archive table or update summary statistics.

2.3

Syntax & Live Project Examples

Below are the actual triggers defined in our college database schema (database/05_triggers.sql):

1. BEFORE INSERT: Event Capacity Enforcement (trg_check_event_capacity)
Validation & Error Signal
-- DELIMITER command tells MySQL CLI to not terminate the statement at internal semicolons DELIMITER $$ CREATE TRIGGER trg_check_event_capacity BEFORE INSERT ON registrations FOR EACH ROW BEGIN DECLARE current_count INT; DECLARE max_allowed INT; -- 1. Fetch current count of active registrations SELECT COUNT(*) INTO current_count FROM registrations WHERE event_id = NEW.event_id; -- 2. Fetch maximum capacity configured for this event SELECT max_capacity INTO max_allowed FROM events WHERE event_id = NEW.event_id; -- 3. If capacity reached, abort transaction with standard SQLSTATE 45000 IF current_count >= max_allowed THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Registration rejected: Event is already at full capacity!'; END IF; END$$ DELIMITER ;
2. AFTER INSERT: Security Audit Logging (trg_audit_new_registration)
Audit Trail Logging
DELIMITER $$ CREATE TRIGGER trg_audit_new_registration AFTER INSERT ON registrations FOR EACH ROW BEGIN -- Automatically insert audit metadata into the auxiliary security table INSERT INTO registration_audit ( registration_id, student_id, event_id, action_type, performed_at, performed_by ) VALUES ( NEW.registration_id, NEW.student_id, NEW.event_id, 'INSERT', NOW(), USER() ); END$$ DELIMITER ;
Critical MySQL Trigger Limitation: Error 1442 (Mutating Table) In MySQL, a trigger cannot modify the same table that caused it to fire. For instance, an AFTER INSERT ON registrations cannot execute an UPDATE registrations SET .... Attempting this throws ERROR 1442: Can't update table 'registrations' in stored function/trigger because it is already used by statement which invoked it to prevent infinite recursion.

Practice Exercises

Exercise 2.1 (Beginner) BEFORE UPDATE

Prevent GPA Decreasing Below Zero:

Write a BEFORE UPDATE trigger named trg_validate_gpa on table students that checks if NEW.gpa < 0.00. If so, raise an error with SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'GPA cannot be negative';.

Hint:
CREATE TRIGGER trg_validate_gpa BEFORE UPDATE ON students FOR EACH ROW BEGIN IF NEW.gpa < 0.00 THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'GPA cannot be negative'; END IF; END;
Exercise 2.2 (Advanced) AFTER DELETE

Student Deletion Archive Trigger:

Explain why an AFTER DELETE trigger cannot use NEW.student_id, and write the SQL statement to copy the deleted student's OLD.student_id, OLD.roll_no, and deletion timestamp into an archive table named deleted_students.

Hint: When a row is deleted, there is no "new" incoming row — only the row that previously existed (OLD)!
CREATE TRIGGER trg_archive_student AFTER DELETE ON students FOR EACH ROW BEGIN INSERT INTO deleted_students(student_id, roll_no, deleted_at) VALUES (OLD.student_id, OLD.roll_no, NOW()); END;
