3. Relational Database Constraints

Master declarative integrity enforcement in MySQL 8 — discover how PRIMARY KEY, FOREIGN KEY, UNIQUE, CHECK, NOT NULL, and DEFAULT guarantee schema validity at the engine level.

3.1

Data Integrity & Constraint Rules

A database constraint is a declarative rule defined on a column or table that the database engine enforces on every single INSERT and UPDATE statement. If any incoming data violates the constraint, MySQL immediately rejects the transaction and preserves data integrity.

PRIMARY KEY
Row Identity

Uniquely identifies each tuple in the table. Must be unique and implicitly NOT NULL. Exactly one PK per table.

FOREIGN KEY
Referential Integrity

Enforces relationships between parent and child tables. Value must exist in the referenced table or be NULL.

UNIQUE
Alternate Key

Ensures no two rows have the same value. Multiple UNIQUE keys allowed per table. MySQL allows multiple NULLs in UNIQUE columns.

NOT NULL
Mandatory Presence

Guarantees that a column cannot store NULL missing values. Essential for names, dates, and primary keys.

CHECK
Domain Predicate (MySQL 8)

Validates Boolean expressions (e.g., gpa BETWEEN 0.00 AND 10.00). Fully parsed and enforced in MySQL 8!

DEFAULT
Fallback Value

Supplies an automatic fallback value if the inserting statement omits the column during an INSERT.

3.2

Primary Key, Unique & Foreign Key Referential Actions

Primary Key vs Unique Constraint
Characteristic PRIMARY KEY UNIQUE Constraint
Quantity per Table Strictly only 1 per table. Multiple permitted on any columns.
NULL Value Handling Cannot be NULL (implicitly NOT NULL). In InnoDB, allows multiple NULL entries (NULL != NULL).
Clustering Index Forms the table's clustered index in InnoDB. Creates a secondary non-clustered B-Tree index.
Foreign Key Referential Integrity Actions

When a parent row (e.g., in departments) is deleted or updated, what happens to referencing child rows in students?

CASCADE

Deletes or updates child records automatically when the parent row is deleted/updated.

RESTRICT / NO ACTION

Default behavior. Prevents deleting or updating the parent row if child rows reference it.

SET NULL

Sets the child foreign key column to NULL when the parent record is deleted.

SET DEFAULT

Sets child foreign key to its column default (rarely supported by InnoDB).

3.3

CHECK, NOT NULL & DEFAULT in MySQL 8

MySQL 8 CHECK Constraint Enforcement

In MySQL 5.7 and older, CHECK clauses were parsed for compatibility but ignored by the storage engine. MySQL 8.0+ strictly enforces CHECK constraints!

CONSTRAINT chk_student_gpa CHECK (gpa >= 0.00 AND gpa <= 10.00)
DEFAULT vs NOT NULL Distinction

DEFAULT only supplies a value if the column is omitted from the INSERT list. If you explicitly insert NULL into a column marked NOT NULL DEFAULT 'Active', MySQL throws an error — DEFAULT does not overwrite an explicit NULL!

status VARCHAR(20) NOT NULL DEFAULT 'Active' -- INSERT (col) VALUES (NULL) -> Error 1048!

Write an ALTER TABLE statement on students to add a constraint named chk_valid_semester that requires semester BETWEEN 1 AND 8.

Hint: ALTER TABLE students ADD CONSTRAINT chk_valid_semester CHECK (semester BETWEEN 1 AND 8);
Exercise 3.2 (Advanced) ON DELETE CASCADE

Course Registrations Cascade Rule:

Explain why deleting a student currently causes an error if the foreign key in registrations uses ON DELETE RESTRICT, and write the DDL required to change it to ON DELETE CASCADE.

Hint: RESTRICT rejects deletion of a parent record as long as referencing child rows exist to prevent orphaned data. To change it:
ALTER TABLE registrations DROP FOREIGN KEY fk_reg_student;
ALTER TABLE registrations ADD CONSTRAINT fk_reg_student FOREIGN KEY (student_id) REFERENCES students(student_id) ON DELETE CASCADE;
