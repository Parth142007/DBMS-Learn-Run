1. Introduction to Database Design & Modification Anomalies

Understand the goals of relational database design — why unnormalized "flat" tables lead to harmful data redundancy, inconsistent states, and catastrophic Insertion, Update, and Deletion anomalies.

1.1

What is Database Design?

Database design is the systematic process of organizing data into a collection of well-structured relational tables, defining the columns, primary keys, foreign keys, and integrity constraints that accurately model a real-world enterprise.

The fundamental goal of good database design is to ensure that each fact is recorded in exactly one place. When an enterprise combines unrelated entities into a single monolithic table, severe architectural problems arise.

1. Data Redundancy

The same attribute values (like student name or instructor name) are repeated across dozens or thousands of rows, consuming excess disk storage.

2. Data Inconsistency

When duplicated information is updated in one row but not another, contradictory facts exist in the database simultaneously.

3. Storage Inefficiency

Indexes bloat, memory buffer pools waste valuable RAM caching repeated strings, and backup file sizes expand unnecessarily.

4. Application Fragility

Software engineers must write convoluted multi-row update queries in application code to preserve basic data sanity.

1.3

The Three Relational Modification Anomalies

Anomaly 1
Insertion Anomaly

Problem: You cannot insert information about a course without also inserting a student who enrolled in it!

Why: If the primary key is composite (StudentID, CourseID), relational integrity forbids StudentID from being NULL. You cannot introduce course C03 until someone registers!

Anomaly 2
Update Anomaly

Problem: If instructor Sharma is replaced by Verma for course C01, you must update multiple rows across the database.

Why: If the update query misses even a single row, the database enters an inconsistent state where DBMS is taught by two different instructors simultaneously!

Anomaly 3
Deletion Anomaly

Problem: If Neha (102) cancels her registration, deleting her row unintentionally deletes course C01 or student details!

Why: If Amit drops out of Python (C02), deleting his row permanently erases all institutional record that course C02 exists and that Patil teaches it!

The Solution: Database Normalization Normalization is the formal mathematical technique of decomposing monolithic relations with anomalies into smaller, well-structured relations that preserve all original data and functional dependencies without redundancy.
