4. First Normal Form (1NF) & Attribute Atomicity

Understand the bedrock prerequisite of the relational model — why multivalued attributes, repeating groups, and comma-separated lists violate 1NF, and how to transform unnormalized datasets into pure atomic relations.

4.1

What is First Normal Form (1NF)?

A relational table is in First Normal Form (1NF) if and only if:

  • Atomic Values: Every column contains only atomic (indivisible) values — no sets, arrays, nested tables, or composite sub-records.
  • No Repeating Groups: There are no multiple columns storing the same type of data (e.g. Phone1, Phone2, Phone3).
  • Unique Rows: Every row must be unique and identifiable by a Primary Key.
  • Order Independence: The order of rows and columns has no bearing on relational semantics.
What Does "Atomicity" Really Mean? Atomicity is defined by how the application uses the data, not by string length or character count! A column storing a book title like 'Database System Concepts' is completely atomic if the system treats it as a single unit. However, a column storing 'Sharma, Patil' is non-atomic because it packs multiple distinct instructors into one field.
4.2

Why Comma-Separated Values Harm Relational Engines

Software beginners often store multiple items in a single column using commas (e.g. Courses = "DBMS, Python"). In MySQL, this creates severe engineering penalties:

1. Broken Indexes

B-Tree indexes cannot index elements inside text strings. Searching requires slow full table scans using LIKE '%Python%'.

2. No Foreign Keys

MySQL InnoDB cannot enforce foreign key referential integrity on individual values locked inside a text string.

3. Aggregates Disabled

You cannot run standard SQL aggregate queries like COUNT(CourseID) or GROUP BY CourseID.

4. Substring Hazards

A search for 'Java' accidentally matches 'JavaScript' unless complex regex parsing is applied.

4.4

Practice Exercises

Exercise 4.1 Repeating Groups

Repeating Columns vs 1NF:

A table has columns: STUDENT(RollNo, Name, Phone1, Phone2, Phone3). Explain why this violates First Normal Form even if each column holds a single phone number.

Hint: Phone1, Phone2, Phone3 represent a repeating group. If a student has 4 phones, the schema must be altered; if a student has only 1 phone, columns waste space storing NULLs. The solution is a separate related table STUDENT_PHONE(RollNo, Phone).
Exercise 4.2 Composite Key Emergence

Primary Key Selection in 1NF:

When an unnormalized relation with a single-attribute key is converted to 1NF by splitting a multi-valued attribute into separate tuples, what almost always happens to the relation's primary key?

Hint: The original key values now repeat across multiple rows, so the original key alone can no longer guarantee uniqueness. The primary key becomes a composite key combining the original key and the repeating attribute!
