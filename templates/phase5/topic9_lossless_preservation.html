9. Lossless Join Decomposition & Dependency Preservation

Explore the two fundamental mathematical guarantees of relational decomposition: preventing spurious tuples with lossless joins and enabling efficient local constraint enforcement through dependency preservation.

9.1

Lossless Join & The Threat of Spurious Tuples

When decomposing a relation $R$ into smaller relations $R_1, R_2, \dots, R_k$, the decomposition is called lossless (or non-additive) if joining the decomposed tables via natural join ($\bowtie$) reconstructs the exact original relation without losing any data or adding false records:

$R_1 \bowtie R_2 \bowtie \dots \bowtie R_k = R$
What Happens in a "Lossy" Decomposition? Spurious Tuples!

A "lossy" decomposition does not delete rows; instead, it causes a loss of information by creating spurious (fake/hallucinated) tuples when the tables are joined back together.

1. Original Relation: EMP_PROJECT
EmpDeptProject
AmitITP1
NehaITP2
Only 2 true facts exist.
2. Bad Decomposition (On Dept)
R1(Emp, Dept): Amit-IT, Neha-IT
R2(Dept, Project): IT-P1, IT-P2
Common attribute is Dept (NOT a key in either table!).
3. Rejoined: $R_1 \bowtie R_2$
EmpDeptProject
AmitITP1
AmitITP2 ✗
NehaITP1 ✗
NehaITP2
2 spurious tuples created! Amit never worked on P2, and Neha never worked on P1.
Critical Rule: In database design, a lossy decomposition is unacceptable because it destroys data integrity. Every normalization step must be mathematically proven to be lossless.
9.2

The Binary Lossless Decomposition Test

How do we test if a decomposition of relation $R$ into two relations $R_1$ and $R_2$ is lossless? There is an elegant and fast mathematical theorem based on functional dependencies:

Fundamental Lossless Decomposition Theorem

A binary decomposition of $R$ into $(R_1, R_2)$ is lossless with respect to functional dependency set $F$ if and only if at least ONE of the following dependencies is in the closure $F^+$:

Condition 1: $(R_1 \cap R_2) \to R_1$
Condition 2: $(R_1 \cap R_2) \to R_2$

Plain English Meaning: The common attributes $(R_1 \cap R_2)$ must form a superkey for at least one of the decomposed relations ($R_1$ or $R_2$).

Worked Step-by-Step Test:

Given: $R(A, B, C)$, $F = \{A \to B\}$.

Decomposition: $R_1(A, B)$ and $R_2(A, C)$.

  1. Calculate intersection: $R_1 \cap R_2 = \{A\}$.
  2. Compute attribute closure of intersection: $\{A\}^+$ under $F$:
    $\{A\}^+ = \{A, B\}$.
  3. Check Condition 1: Does $\{A\}^+$ contain all attributes of $R_1(A, B)$?
    Yes! $\{A, B\} \subseteq \{A\}^+$. Thus, $(R_1 \cap R_2) \to R_1$ holds!
Conclusion: The decomposition into R1(A,B) and R2(A,C) is 100% Lossless!
9.3

Dependency Preservation & Integrity Enforcement

A decomposition is dependency preserving if all original functional dependencies in $F$ can be enforced by checking the individual decomposed relations, without having to perform a join between them.

Why Dependency Preservation Matters

In production, DBMS enforces constraints on every INSERT and UPDATE:

  • Preserved: Can be verified using standard single-table PRIMARY KEY or UNIQUE constraints in milliseconds.
  • Not Preserved: Enforcing the business rule requires writing an expensive BEFORE INSERT trigger that joins multiple tables, causing major performance bottlenecks!
Formal Definition

Let $F_i$ be the set of dependencies in $F^+$ that include only attributes belonging to $R_i$ (projection of $F$ onto $R_i$).

The decomposition is dependency preserving if:

$(F_1 \cup F_2 \cup \dots \cup F_k)^+ = F^+$
Crucial Takeaway: We can always achieve a 3NF decomposition that is both lossless and dependency-preserving. For BCNF, lossless join is guaranteed, but dependency preservation is not always guaranteed!

Practice Exercises with Guided Solutions

Exercise 1 Binary Lossless Test

Relation $R(A, B, C, D)$ has $FD = \{A \to B, B \to C\}$. Decomposed into $R_1(A, B)$ and $R_2(A, C, D)$.
Question: Is this decomposition lossless?

Hint: Find $R_1 \cap R_2$. Then compute $(R_1 \cap R_2)^+$. Does it cover either $R_1$ or $R_2$?
Solution:
1. $R_1 \cap R_2 = \{A\}$.
2. $\{A\}^+ = \{A, B, C\}$ (using $A \to B$ and $B \to C$).
3. Notice that $R_1 = \{A, B\}$. Since $\{A, B\} \subseteq \{A\}^+$, we have $(R_1 \cap R_2) \to R_1$.
4. Therefore, the decomposition is 100% Lossless!
Exercise 2 Dependency Preservation Check

Relation $R(A, B, C)$ has $FD = \{A \to B, B \to C, C \to A\}$. Decomposed into $R_1(A, B)$ and $R_2(B, C)$.
Question: Is the dependency $C \to A$ preserved?

Hint: What dependencies are covered in $R_1$? In $R_2$? Can $C \to A$ be derived from $(F_1 \cup F_2)$ using Armstrong's transitivity?
Solution:
1. $F_1 = \{A \to B\}$ (in $R_1(A, B)$).
2. $F_2 = \{B \to C\}$ (in $R_2(B, C)$).
3. Under $F' = F_1 \cup F_2 = \{A \to B, B \to C\}$, $\{C\}^+ = \{C\}$. We CANNOT derive $A$ from $C$ using only $F_1 \cup F_2$!
4. Therefore, $C \to A$ is NOT preserved in this decomposition.
