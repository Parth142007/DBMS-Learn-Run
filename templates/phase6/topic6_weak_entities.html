Lesson 6

Weak Entities & Identifying Relationships

NEPC42 Core Concept
1. What is a Weak Entity?

A Weak Entity is an entity type that does not possess sufficient attributes to form a Primary Key on its own. It is existence-dependent on another entity, termed the Owner Entity (or identifying entity).

Characteristic Strong Entity (Regular) Weak Entity
Primary Key Has its own complete Primary Key. Does not have its own Primary Key. Uses a Partial Key.
Chen ER Symbol Single Rectangle [EMPLOYEE] Double Rectangle [[DEPENDENT]]
Relationship Symbol Single Diamond <Works_For> Double Diamond <<Has_Dependent>> (Identifying Relationship)
Participation Can be Total or Partial. Always Total Participation (====) in the identifying relationship!
Key Identifier Primary Key (Solid Underline: ID) Partial Key / Discriminator (Dashed Underline: Name)
Conceptual Modeling Construct ≠ Special SQL Table Type:
A weak entity is a conceptual abstraction in the ER model to prevent creating artificial global IDs when not needed. In physical MySQL 8, there is no CREATE WEAK TABLE statement! It is implemented as a standard relational table whose Primary Key is Composite, formed by joining the owner's primary key (as a Foreign Key) with the partial key.
2. Comprehensive Worked Example: EMPLOYEE & DEPENDENT

Consider an enterprise health insurance system. An employee has insurance coverage that extends to their family dependents (spouse, children):

Chen Weak Entity Notation: Double Rectangle = Weak Entity; Double Diamond = Identifying Relationship; Double Line = Mandatory Total Participation; Dashed Underline = Partial Key (Discriminator).
Why DependentName is Only a Partial Key:

An employee (Employee 101) might have a son named "Aarav". Another completely unrelated employee (Employee 205) might also have a son named "Aarav".

Within the family of Employee 101, "Aarav" is distinct. But across the entire company database, "Aarav" is NOT globally unique! Hence, DependentName is a partial key (discriminator).

Conversion to Relational Tables (MySQL 8 DDL):
-- Parent Strong Table
CREATE TABLE employees (
    employee_id INT PRIMARY KEY,
    employee_name VARCHAR(100) NOT NULL
);

-- Child Weak Table
CREATE TABLE dependents (
    employee_id INT NOT NULL,       -- Owner's PK as FK
    dependent_name VARCHAR(50) NOT NULL, -- Partial Key
    relationship VARCHAR(30) NOT NULL,
    PRIMARY KEY (employee_id, dependent_name), -- Composite PK!
    FOREIGN KEY (employee_id) REFERENCES employees(employee_id)
        ON DELETE CASCADE -- Existence Dependency!
);
