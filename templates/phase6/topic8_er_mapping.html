Lesson 8

Systematic Mapping: ER Diagrams to Relational Schemas

NEPC42 Core Concept
1. The Standard 7-Step ER-to-Relational Mapping Algorithm

Transforming a conceptual ER diagram into a normalized relational database schema follows a strict, deterministic 7-step engineering algorithm. Every ER construct maps directly to relational tables, foreign keys, or integrity constraints:

Step # ER Construct Relational Mapping Rule College Schema Example
Step 1 Strong Entity Types Create a relation $R$ containing all simple attributes. Choose the key attribute as PRIMARY KEY. DEPARTMENT(dept_id, dept_name)
Step 2 Composite Attributes Flatten composite attributes into their atomic components. Do not create a separate column for the composite parent name. Address → street, city, state, zip
Step 3 Weak Entity Types Create a relation $W$. Include all simple attributes + the Primary Key of the owner entity as a FOREIGN KEY. The Primary Key of $W$ is the combination: PRIMARY KEY (owner_pk, partial_key). DEPENDENT(emp_id, dep_name, relation)
Step 4 1:1 Binary Relationships Foreign Key Approach: Place the PK of one entity as an FK in the other relation. Place it on the side with Total Participation to avoid NULLs. Add a UNIQUE constraint on the FK column. DEPARTMENT(dept_id, dept_name, head_id UNIQUE FK)
Step 5 1:N Binary Relationships Foreign Key on the N-Side: Identify the relation representing the "Many" ($N$) side. Add the Primary Key of the "One" side as a FOREIGN KEY in the $N$-side relation. STUDENT(student_id, name, dept_id FK)
Step 6 M:N Binary Relationships Create Junction Relation: Create a new associative table $J$. Include the Primary Keys of both participating entities as FOREIGN KEYS. Combine both FKs to form the composite PRIMARY KEY. Include any relationship attributes. ENROLLMENT(student_id FK, course_id FK, grade)
Step 7 Multivalued Attributes Create a dedicated new relation $M$. Include the multivalued attribute + the owner's Primary Key as a FOREIGN KEY. The composite Primary Key is PRIMARY KEY (owner_pk, attribute_val). STUDENT_PHONE(student_id FK, phone_num)
2. Full Worked Example: Side-by-Side ER & Relational Schema

Observe how the complete college management system ER diagram is translated into clean, normalized MySQL 8 tables without data redundancy:

Conceptual ER Model Business Rules
  • DEPARTMENT: Strong entity with Key DepartmentID and attribute DepartmentName.
  • INSTRUCTOR: Strong entity with Key InstructorID and InstructorName. Employs is 1:N (Dept to Instructor). Heads is 1:1.
  • COURSE: Strong entity with Key CourseID and CourseName. Belongs To Dept is 1:N.
  • STUDENT: Strong entity with Key StudentID and StudentName. Majors in Dept is 1:N.
  • ENROLLS: M:N relationship between Student and Course with relationship attribute Grade.
Resulting Relational Schema & DDL 
-- 1. DEPARTMENT
CREATE TABLE departments (
    department_id INT PRIMARY KEY,
    department_name VARCHAR(100) NOT NULL
);

-- 2. INSTRUCTOR (FK to department)
CREATE TABLE instructors (
    instructor_id INT PRIMARY KEY,
    instructor_name VARCHAR(100) NOT NULL,
    department_id INT NOT NULL,
    FOREIGN KEY (department_id) REFERENCES departments(department_id)
);

-- 3. COURSE (FK to department)
CREATE TABLE courses (
    course_id VARCHAR(10) PRIMARY KEY,
    course_name VARCHAR(100) NOT NULL,
    department_id INT NOT NULL,
    FOREIGN KEY (department_id) REFERENCES departments(department_id)
);

-- 4. STUDENT (FK to department)
CREATE TABLE students (
    student_id INT PRIMARY KEY,
    student_name VARCHAR(100) NOT NULL,
    department_id INT NOT NULL,
    FOREIGN KEY (department_id) REFERENCES departments(department_id)
);

-- 5. ENROLLMENT (M:N Associative Junction Table)
CREATE TABLE enrollments (
    student_id INT NOT NULL,
    course_id VARCHAR(10) NOT NULL,
    grade VARCHAR(2) NULL,
    PRIMARY KEY (student_id, course_id), -- Composite PK!
    FOREIGN KEY (student_id) REFERENCES students(student_id),
    FOREIGN KEY (course_id) REFERENCES courses(course_id)
);
