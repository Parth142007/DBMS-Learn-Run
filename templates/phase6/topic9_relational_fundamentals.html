Relational Model Fundamentals & Integrity Constraints

NEPC42 Core Concept
1. Mathematical Foundations of the Relational Model

Proposed in 1970 by Dr. E.F. Codd (IBM), the Relational Model grounded database management in rigorous first-order predicate logic and mathematical set theory. Rather than physical pointers (as in hierarchical or network databases), data is organized into simple two-dimensional mathematical relations:

Formal Relational Term Informal SQL Term Formal Definition & Mathematical Meaning
Relation Table A mathematical relation $R$ defined over domains $D_1, D_2, \dots, D_n$ is a subset of the Cartesian product: $R \subseteq D_1 \times D_2 \times \dots \times D_n$.
Tuple Row / Record An ordered list of $n$ values $t = \langle v_1, v_2, \dots, v_n \rangle$ where each value $v_i \in D_i$.
Attribute Column / Field A named role played by a domain in a relation schema, denoting a specific property.
Domain Data Type / Permitted Set A set of atomic (indivisible) values. Example: Domain of DepartmentID is positive integers $\mathbb{Z}^+$.
Relation Schema Table Structure (DDL) Denoted $R(A_1:D_1, A_2:D_2, \dots, A_n:D_n)$, specifying the relation name, attribute names, and domain definitions.
Relation Instance Current Table Data (State) The specific set of tuples present in the relation at a given moment in time: $r(R) = \{t_1, t_2, \dots, t_m\}$.
Degree (Arity) Number of Columns The total count of attributes in the relation schema. For $STUDENT(ID, Name, Dept, GPA)$, Degree = 4.
Cardinality Number of Rows The total count of tuples currently stored in the relation instance. Changes dynamically with INSERTs/DELETEs.
Key Differences: Pure Mathematical Relations vs. Practical SQL Tables
Mathematical Relational Model (Codd)
  • Pure Set Semantics: A set by definition contains NO duplicate elements. Two identical tuples cannot exist.
  • No Tuple Ordering: Sets are unordered: $\{t_1, t_2\} \equiv \{t_2, t_1\}$.
  • No Attribute Ordering: Attributes are identified strictly by name, not index position.
  • Strict First Normal Form: All values must be strictly atomic.
Practical Commercial SQL (MySQL 8)
  • Multiset / Bag Semantics: Tables permit duplicate rows unless constrained by a PRIMARY KEY or UNIQUE index.
  • Physical Ordering Exists: Rows are stored physically ordered by the clustered primary key index (B+Tree).
  • Column Ordinal Position: Columns have fixed left-to-right positions (e.g. SELECT * returns columns in order of definition).
  • NULL Semantics: Supports SQL 3-valued logic (UNKNOWN).
2. Core Relational Integrity Constraints

Relational databases maintain data consistency via three foundational integrity rules:

Rule 1
Entity Integrity

Rule: No primary key value can be NULL! Every tuple must be definitively identifiable.

MySQL Enforcement: PRIMARY KEY columns automatically enforce NOT NULL UNIQUE.
Rule 2
Referential Integrity

Rule: A foreign key value in a child relation must either match a valid existing primary key in the parent relation, or be entirely NULL.

MySQL Enforcement: FOREIGN KEY ... REFERENCES blocks orphaned records.
Rule 3
Domain Integrity

Rule: Every value stored in an attribute must be an atomic element belonging to that attribute's defined domain.

MySQL Enforcement: Data types (INT, VARCHAR) and CHECK (gpa >= 0) constraints.
NULL Values & 3-Valued Logic:
In relational algebra and SQL, NULL is NOT zero (0) and NOT an empty string (''). It represents unknown, unrecorded, or inapplicable information. Comparing any value to NULL using = evaluates to UNKNOWN, not TRUE or FALSE! Hence, SQL provides explicit operators IS NULL and IS NOT NULL.
