Phase 7 — Transactions & Concurrency

Master Transaction Boundaries, ACID Properties, State Transitions, Concurrency Phenomena, Conflict Serializability, Lock-Based Protocols (2PL), Deadlocks, and Write-Ahead Logging (WAL) Recovery.

Main Dashboard Phase 6: ER Model Schema Inspector
Module Learning Objectives

By completing this comprehensive interactive module on Transaction Processing and Concurrency Control, students will be able to:

Define Transaction Boundaries (`START TRANSACTION`, `COMMIT`, `ROLLBACK`) and analyze atomicity in financial transfers.
Explain and test all four ACID Properties (Atomicity, Consistency, Isolation, Durability) with practical scenarios.
Trace Transaction State Transitions (Active, Partially Committed, Committed, Failed, Aborted, Terminated).
Identify and diagnose Concurrency Anomalies: Lost Updates, Dirty Reads, Non-Repeatable Reads, Phantoms, and Inconsistent Summaries.
Construct Precedence Graphs, detect directed cycles, and verify Conflict Serializability algorithmically.
Simulate Lock-Based Protocols (Shared $S$ / Exclusive $X$) and enforce Two-Phase Locking (2PL) variants.
Detect Deadlocks via Wait-For Graphs (WFG), select victim transactions, and simulate automated recovery.
Execute Write-Ahead Logging (WAL) crash recovery with LSNs, Checkpoints, and Undo/Redo calculations.
