Introduction to Database Transactions

NEPC42 Core Concept
1. What is a Database Transaction?

A Database Transaction is a single logical unit of database operations (reads, writes, updates, deletes) that must be executed in its entirety or not at all. Real-world business operations rarely map to a single isolated SQL statement; they typically require a sequence of related steps that must succeed together to maintain business integrity.

1. START TRANSACTION
Transaction Boundary Start

Signals the database engine (e.g. MySQL InnoDB) that subsequent DML statements form a single cohesive unit of work.

2. COMMIT
Successful Completion

Permanently records all modifications to the database storage. Once committed, the changes are durable and visible to subsequent operations.

3. ROLLBACK
Failure Recovery

Reverts all modifications made during the transaction. The database is restored to the exact consistent snapshot it had before the transaction began.

Transaction Consistency Rule: A transaction transforms the database from one valid, consistent state to another valid, consistent state. While the transaction is in progress, intermediate, temporarily inconsistent states may exist in memory; however, these states must never be exposed or permanently stored if a failure occurs.
2. The Bank Transfer Problem: Why Boundaries Matter

Consider two bank accounts: Account A with an initial balance of ₹5,000, and Account B with an initial balance of ₹3,000. The system invariant is that total wealth in this isolated scope is ₹8,000.

Transfer Workflow: Transfer ₹1,000 from A to B
-- Transaction Boundary Begins
START TRANSACTION;

-- Step 1: Read balance of Account A (₹5,000) and verify A >= 1000
SELECT balance FROM accounts WHERE account_id = 'A' FOR UPDATE;

-- Step 2: Deduct ₹1,000 from Account A
UPDATE accounts SET balance = balance - 1000 WHERE account_id = 'A';  -- A is now ₹4,000

-- [CRITICAL VULNERABILITY POINT]: What if a server crash, OS failure, or network cut happens here?

-- Step 3: Credit ₹1,000 to Account B
UPDATE accounts SET balance = balance + 1000 WHERE account_id = 'B';  -- B is now ₹4,000

-- Step 4: Commit both changes together
COMMIT;
Without Transaction Control (Catastrophic)

If Step 2 succeeds and the server crashes before Step 3 runs:

  • Account A has ₹4,000.
  • Account B still has ₹3,000.
  • Result: ₹1,000 has disappeared from the bank! Total system money dropped to ₹7,000.
With RDBMS Transactions (Safe)

When the database restarts, the recovery manager inspects the log:

  • The transaction never reached a COMMIT record.
  • An automatic ROLLBACK restores Account A back to ₹5,000.
  • Result: Total money remains ₹8,000. No money is lost or created.
