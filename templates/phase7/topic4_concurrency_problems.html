Lesson 4

Concurrent Execution & Concurrency Anomalies

NEPC42 Core Concept
1. Why Execute Transactions Concurrently?

If an enterprise RDBMS processed every transaction strictly one by one in serial order, a single slow query running a complex analytical aggregation would block thousands of quick user lookups. Databases allow concurrent execution (interleaving operations of multiple transactions) to achieve three vital operational goals:

1. Increased Throughput
Transactions per Second (TPS)

Significantly increases the total number of transactions processed per second by utilizing idle CPU cores while other transactions await disk I/O.

2. Hardware Utilization
Parallel CPU & Disk Access

Overlap CPU computation with asynchronous NVMe/SSD buffer pool page reads and network socket transmissions.

3. Reduced Waiting Time
Low Latency for Short Queries

Prevents short, high-priority write transactions (e.g. checkout click) from waiting in an artificial queue behind hours-long batch reporting jobs.

The Concurrency Dilemma: While concurrent execution drastically improves performance, unrestrained concurrent access to the same shared data items without proper concurrency control causes severe data corruption, known as concurrency phenomena or anomalies.
2. The Five Classic Concurrency Anomalies
Anomaly 1: The Lost Update Problem (Write-Write Overwrite)

Definition: Two transactions read the same data item $X$ simultaneously and calculate updates independently. The transaction that writes last completely overwrites and obliterates the update made by the earlier transaction, without having factored in that update.

Step Transaction T1 (Deposit ₹50) Transaction T2 (Deposit ₹20) Database Value (X)
1 Read X (100) — 100
2 — Read X (100) 100
3 Write X = 100 + 50 = 150 — 150
4 — Write X = 100 + 20 = 120 120 (OVERWRITTEN!)
Outcome: T1 deposited ₹50 and T2 deposited ₹20. The final balance should be ₹170, but it is ₹120. T1's ₹50 deposit was lost!
Anomaly 2: The Dirty Read Problem (Reading Uncommitted Data)

Definition: Transaction T1 updates data item $X$. Before T1 commits or rolls back, transaction T2 reads the modified value of $X$. T1 subsequently aborts and rolls back. T2 has acted upon a value that never existed in the official database state!

Step Transaction T1 (Transfer) Transaction T2 (ATM Cash Out) Database Value (X)
1 Write X = 5,000 (Bonus credit) — 5,000 (In Memory)
2 — Read X (5,000) & Dispense ₹5,000 Cash 5,000
3 ROLLBACK (Transfer Aborted) — 0 (Restored)
Outcome: T2 dispensed real cash based on a phantom bonus credit that was rolled back immediately afterward.
Anomaly 3: The Non-Repeatable (Fuzzy) Read

Definition: Transaction T1 reads a row $X$. Concurrently, transaction T2 modifies or deletes that row and commits. When T1 reads row $X$ again within the same transaction, it sees a different value or finds the row missing!

Step Transaction T1 (Discount Evaluator) Transaction T2 (Price Updater) Product Price (P)
1 Read P (₹100) — ₹100
2 — Update P = ₹150; COMMIT; ₹150
3 Read P again (Sees ₹150!) — Changed mid-transaction
Outcome: T1 received two different values for the exact same query in the same transaction, breaking repeatability.
Anomaly 4: The Phantom Read Problem

Definition: Transaction T1 executes a query with a predicate/range (e.g. WHERE gpa > 9.0) and retrieves $N$ rows. Concurrently, transaction T2 inserts a new row satisfying that predicate and commits. When T1 re-executes the exact same query, it discovers a new "phantom" row that was not present previously!

Non-Repeatable Read vs Phantom Read: Non-Repeatable Read involves modifying or deleting an existing individual row. Phantom Read involves inserting new rows that match a range or predicate search condition.
Anomaly 5: Inconsistent Analysis (Incorrect Summary)

Definition: Transaction T1 computes an aggregate summary (e.g., SUM(balance) across accounts A, B, and C). Concurrently, transaction T2 transfers funds from C to A. If T1 reads A before the transfer, but reads C after the debit, T1's sum will miss the transferred funds!

Outcome: Total reported by T1 is lower than the true sum because it observed a partially updated state.
